# Validation Claims Manifest

Every accuracy claim in the README carries a row here: value, measurement
date, commit, and the exact reproduction command. A number without a row is
unverified; new claims land with a row.

Each row carries a stable **ID**. Validation-table rows in `README.md` must
cite their ID — `tests/python/test_validation_claims.py` fails the build if
the two sides disagree, if a cell is empty, or if a reproduction command
references a script/data path that no longer exists. That last check is
what catches a renamed script silently orphaning a claim.

Two further columns are checked by the same test:

- **Sample** says how independent the number is from anything fitted: `in-sample`,
  `out-of-sample`, `mixed: <what overlaps>`, or `n/a` when nothing was fitted.
- **Status** is `current`, or `STALE(<reason>)` when a later change to the
  library affects something the number depends on (for example
  `STALE(exact-epoch)`) and the row has not been re-measured yet. With
  `BALLISTIC_RELEASE_GATE=1`, any stale row fails the build.

The test also checks that every `--flag` in a reproduction command exists in
that script's argument parser.

Where a value cell says "previous build" or "previous measurement", it
records how the number moved when the library changed, and why; the current
value is the one in bold at the start of the cell.
